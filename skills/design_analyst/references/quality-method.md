# 以安全需求覆盖为目标的设计调查

## [DESIGN_ANALYST-07] 建立安全相关行为库存，而非组件摘要

先区分本次变更、既有依赖、外部责任和未选方案。每个涉及权限、机密性、完整性或可用性的流程建立一行：业务目的；主体与控制能力；资产及归属；入口；跨越的信任边界；正常状态转移；失败/撤销/重试；已声明保护；未知项。无对应业务事实的维度记“不涉及及理由”，不得补造流程。

事实选择采用安全影响试验：如果删除这条事实，后续是否会错判一个主体能做什么、保护哪个对象、什么时候控制失效，或谁承担责任？会则保留；纯开发计划、测试比例、内部函数接线、非安全指标不单独充当 CONTROL。可为理解流程保留必要 MODULE/关系事实，但不要把它们描述成安全承诺。

同一名称可能表达不同语义。JWT 中有 Node 信息不意味着令牌绑定 Node 的存活；有任务 ID 不意味着它是授权凭证；有日志不意味着记录完整令牌。分别建立“信息携带”“授权依据”“生命周期约束”的事实，不能按关键词合并。

## [DESIGN_ANALYST-08] 按控制变化点寻找容易遗漏的事实

沿一次真实业务完成路径追踪下列变化点；每一项返回原文，而不是枚举安全标准：

| 变化点 | 调查动作 | 会影响的后续要求 |
| --- | --- | --- |
| 用户身份转为后台服务身份 | 找任务创建者、可信消息来源、对象集合如何传递 | 防止服务凭证扩大用户授权 |
| 同一对象在创建/执行/下载之间改变 | 找授权、归属、撤销或取消的生效约定 | 检查在正确时刻约束正确对象 |
| 数据复制到缓存、日志、导出文件 | 找新增读者、存储责任、引用凭证及删除关系 | 避免只保护主数据库 |
| 同一动作有批量/管理员/回调入口 | 找合法例外、注册关系、是否复用控制 | 防止主入口结论扩大到旁路 |
| 可选功能、升级或降级 | 建立“功能开关—影响动作—既有对象行为”表 | 防止把停发、停验证、停审计混成一个开关 |
| 失败、超时、重试、部分成功 | 找失败后仍发生的更新、回滚边界和重复动作 | 确定计时、幂等及清理约束 |

不要要求每篇文档必须涉及所有维度。没有支付、浏览器或多租户事实就不能制造相应资产、入口或合规范围。

## [DESIGN_ANALYST-09] 输出面向覆盖的交接

summary 用简短“流程/资产 → 相关 Fact ID → 已知保护或具体未知”的清单交接。每个真实敏感流程至少关联一个事实或具体 gap；只把安全名词列齐不算覆盖。gaps 说明缺少哪个关系、会使哪个控制的必要性无法确定，不泛写“需要更多信息”。这份清单进入本次任务存档，不新增未经声明的字段。

把原文没有写保护机制与业务关系未知分开：若客户归属、非可信对象选择、泄露后果都已知，只是没写授权机制，应输出这些已知关系，允许下游推导控制；不能将整个问题降为未知。若连对象是否私有都未知，则保留未知，不断言所有对象必须登录访问。

## 调查样例：异步文档导出

设计说明：客户各自拥有账单，用户提交账单 ID，工作器用服务账号生成文件；下载凭任务 ID；用户取消后任务不得继续。未写租户鉴权。

应保留：客户—账单归属；调用者控制对象 ID；工作器使用不同身份；文件是账单副本；下载入口及其标识符；取消后的禁止转移。这些共同支撑授权、身份范围传递、结果读取与取消并发控制的推导。

不能写“已实现租户隔离”“任务 ID 随机因此下载安全”；也不能因为没写鉴权就只交付“有 API、有队列、有存储”三个模块。未说明的 ID 熵、文件留存周期、身份提供方写具体 gap，不补造固定值。

## 调查样例：非目标与兼容行为

“本次不改变默认验证行为”说明变更边界，不是“禁止管理员启用其他验证”。“未来可嵌入请求者信息”是未选方案，不是禁止信息记录。把范围事实和真实禁止动作分开，只有实际禁止句才能形成 FORBIDDEN 约束。两节对审计字段名称不一致时保留冲突来源，不凭熟悉程度择一。

## [DESIGN_ANALYST-10] 区分范围事实、许可条件和结果保证

“字段当前只作展示”“没有使用某解释器”是实际数据流或范围事实，不自动等于永久禁止未来任何使用。将当前实现意图与安全不变量分别标出。主体有权下载不等于任务已经完成、未取消或未到期；权限条件、生命周期条件及对象可用性是相互独立的事实。原文只约束发布时，不升级成后台绝不允许生成私有临时数据。
