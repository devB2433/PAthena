# 安全不变量推导与原子化案例

以下使用合成设计，不构成当前项目需求或正式标准原文。

## 案例 A：从业务范围推导隔离要求

材料描述每个客户拥有自己的订单，已认证用户提交导出任务。原文没有直接写“每次查询必须限制租户”。

推导链：客户拥有订单 → 合法用户能选择导出参数 → 读取其他客户订单会破坏既定所有权 → 导出处理必须约束对象范围。若这些关系有原文依据，租户隔离可以作为 INFERRED_SECURITY；不能宣称原文明确规定或标为 PCI_DSS。

控制表述示例：“导出处理读取订单时，只能读取发起主体在当前业务条件下被授权的订单集合。”验收可分别涉及单条范围、批量集合、拒绝未经授权对象。异步执行与结果下载若是不同控制目的，应分别立项；不要一条需求包含隔离、会话撤销、日志留存和文件加密。

若设计明确存在跨客户管理员，保留该授权条件。不能把“只属于本租户”写成排除合法管理员的无条件规则。

## 案例 B：最弱实现能揭示验收漏洞

候选验收只有“导出前检查用户已登录”。一个实现允许任何登录用户选择任意客户 ID，仍满足字面验收，却破坏控制目的。

继续读对象归属、参数来源和权限设计。将身份建立与对象范围授权拆成不同安全行为，分别写允许和拒绝条件。不要自行加一个设计未要求的固定角色名称。

## 案例 C：撤销与缓存

原文明确要求撤销账号访问能力，又说明令牌存在缓存。

调查：撤销影响何种主体、令牌及入口？是否允许缓存延迟？延迟值来自规范句还是性能示例？明确允许的延迟要保留；未定的延迟写 gap，不能造出“立即”或“5 分钟”。

可形成一条关于撤销后访问限制的控制，用不同验收项覆盖文档实际提及的入口和凭证。不要把“有撤销函数”写成验收标准，后续应能检查旧凭证的行为。

## 案例 D：可选配置的条件必须完整

原文：“如启用自定义身份映射，应校验映射结果的授权范围。”

statement 与相关验收项均保留“启用自定义身份映射时”。不得要求所有项目必须支持该映射，也不得要求所有输入都等于示例中的 issuer。通用“避免身份混淆”若另有具体风险依据，可单独作为推导要求，不冒充显式设计要求。

## 案例 E：代码机制与实际运营

原文要求记录敏感操作，并要求生产日志按明确策略留存。

一条机制控制约束实际哪些操作被记录、记录如何归属和如何防止暴露敏感内容；另一项或另一条外部落实要求约束生产日志实际留存。不要把“审计员访谈运维人员”列成代码验收项。

真实外部要求不能因为系统采用静态分析就删除。它的后续结果可能是 NOT_CODE_VERIFIABLE，仍是有效需求。

## 案例 F：不足以推导的推荐做法

文档只说“使用 Web 框架”。不能据此生成某种固定 CSP、特定 WAF 产品、固定密码长度或全部行业控制。需要具体资产、入口和风险链；没有时记录待澄清对象，不为目录覆盖率堆积控制。

有明确可用性目标且攻击者能触发高成本任务时，可以推导相应资源约束。不要机械将全部 DoS 控制排除，也不要为所有函数要求递归深度限制。

## 需求质量复盘

每项都应回答：谁对什么做什么时必须怎样？来源支持哪部分？风险推导依赖什么事实？最弱满足实现还能否破坏目的？条件、允许例外与失败行为是否清楚？

rationale 说明这些关系，不写空泛“出于安全考虑”。acceptance_criteria 每项给出独立判断对象，不混入“已实现”“已通过”等结果。

## 条件、量词与时钟反例（v0.4）

来源：“归档已登记的对象，但不归档仍被任务引用的对象；所有节点同意后开始，任意节点退出后停止。”必须保留登记为正条件、任务引用为负条件。未登记对象归档属于 POLARITY；全部节点退出才停止属于 QUANTIFIER。检查同一句里同时有正条件和否定例外，不能让否定扩散到相邻定义。

来源：“拒绝恢复请求仍更新尝试时间；标记冻结后，再经过管理员配置的一个周期且仍无使用，才最终删除；管理员可以移除冻结标签恢复。”不能移动更新到恢复成功之后（TIMING），不能只计算首次闲置的一个周期（TIMING），不能禁止管理员修改标签（EXCEPTION）。默认七天不等于禁止修改七天（STRENGTH）。

来源：“可以使用指标或审计事件观察失败；管理员可读状态。”不能强制两种手段同时提供，也不能推导只有控制器可读。两个验收项分别要求关闭开关停止与关闭开关开始，则为 INTERNAL_CONTRADICTION。附加“恢复后永不处理之前对象”若原文没规定，属于 UNSUPPORTED_ADDITION，不能称为无关实现细节。上述反例均需落到具体 claim、连续原文与问题码；话题相似不构成支持。
