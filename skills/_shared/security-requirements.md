# 从设计行为推导具体安全需求

## [SECURITY-PATTERNS] 使用边界

这是 PAthena 编写的专业调查与需求示例，参考文末 OWASP 官方资料。Top 10:2025 提供风险视角；ASVS 5.0.0 提供可核验要求的粒度；Cheat Sheet 补充控制方法。以下 P 编号是本项目方法编号，不是 OWASP 条款编号。示例是条件化的控制模式，不是对当前项目事实、合规适用性或已实现情况的声明。

运行时完整加载本文件，不访问外网。仅当设计的实际资产、操作、输入或信任边界满足触发条件，才实例化对应控制。设计没有写保护措施，并不阻止有依据的安全推导；缺少的是业务前提时，记录确切未知，不凭空构造入口。OWASP 方法出处不能代替项目设计引文，也不能冒充已入库合规控制。

## 从类别到具体要求的四步

1. **识别业务暴露**：从原文登记主体、实际动作、对象及归属、可控字段、数据接收者、状态和外部依赖。只抽取组件名不足以完成这步。
2. **识别安全不变量**：对同一动作分别问谁可执行、哪些数据可流出、哪些状态可变化、失败时什么必须保持。每个敏感操作单独考虑；“取消”既有谁能取消的授权问题，也有取消后不能发布的状态完整性问题。
3. **实例化最小控制**：将模式里的对象、主体、入口及边界替换成设计实际名称；控制应阻断明确失效路径。没有具体受保护对象/动作的“防止越权、输入校验、加强日志”不予提交。
4. **写可检查结果**：正文写安全约束；验收写具体拒绝场景及副作用边界，另保留合法例外。不要把有权限写成一定成功；配额、到期、取消、对象不存在等独立业务条件仍适用。不同控制目的拆为不同需求。

覆盖账本以“实际操作 × 适用安全不变量 × 入口/边界”为单位。例如创建、查询、取消、下载分别核对授权；创建鉴权不覆盖取消；取消状态门控不覆盖取消权限。对日志分别核对可归属记录、凭证泄露、敏感正文泄露和篡改权限，不能以已有一条日志需求结算全部。

## [P01] 认证边界与凭证用途（A07）

触发：受保护入口接收会话或访问凭证，或依赖既有身份提供方。
具体需求：受保护请求的主体必须来自服务端验证的身份上下文；缺失、失效或不适用于本服务的凭证不得建立可执行敏感动作的主体。
验收：无效/过期凭证不能创建、读取或取消受保护对象；客户端提交的用户/角色字段不能替代身份上下文。仅在确为 JWT 等签名凭证时检查签名、受信签发方与本服务受众；不假定所有 token 都是 JWT。
边界：既有 SSO 不意味着重建密码库/MFA；登录页、公开资料无需被强制登录。来源：[AUTH]、[T07]。

## [P02] 每个对象与动作的授权（A01）

触发：主体能选择对象 ID、客户 ID、任务 ID、批量集合或敏感操作。
具体需求：对每个实际敏感动作，以可信主体和目标对象核验该动作的权限；未经授权不得读取数据或改变对象状态，未匹配授权规则时拒绝。
验收示例：取消任务前校验“取消该任务”的权限；替换成别人的任务 ID 时任务状态不变；有效委托范围内的管理员不得仅因跨客户而被拒绝。查询/下载/取消分别核对，批量逐对象约束；顺序 ID、随机 ID、按钮隐藏或已登录均不替代授权。
边界：对象归属和委托按设计确定，不把所有跨客户操作一律禁止。授权检查失败或依赖超时不得默认放行。来源：[AUTHZ]、[T01]。

## [P03] 后台代办和可信字段（A01、A08）

触发：后台工作器使用更强服务身份，或外部数据能影响任务所有者、客户、角色、费用、状态等权限/业务字段。
具体需求：工作器的实际对象范围保持在任务发起者的授权范围内；决定权限与归属的字段由可信上下文建立并保持绑定，不能因客户端字段或服务账号权限扩大范围。
验收：修改请求中的客户/所有者不能导出其他客户数据；队列重复或字段缺失不能退化为全库读取；合法委托按其范围处理，仍受取消、到期与资源限制。
边界：从设计明确的请求、任务、服务身份关系推导，不假设能任意伪造私有队列消息，不强制具体消息签名产品。来源：[AUTHZ]、[T08]。

## [P04] 结构化输入与注入边界（A05）

触发：设计确有外部字段进入查询、命令、模板、解释器或结构化解析，不仅是字段名称像“path”。
具体需求：输入不能改变目标解释器中预定的操作结构或权限范围；按实际字段约束类型、集合和业务关系。
验收：SQL 路径把用户值作为绑定数据；可选排序字段映射到受控字段集合，不能拼接任意表达式；批量逐项校验，格式正确的对象 ID 仍须授权。命令路径使用不会将用户值重新解释为命令的调用方式。
边界：不以过滤单引号或“使用 ORM”替代具体保护；没有 SQL/命令路径就不创建对应强制需求，不捏造输入长度值。来源：[SQL]、[INPUT]、[T05]。

## [P05] 浏览器输出中的用户内容（A05）

触发：用户输入、数据库中的外部内容或第三方内容会显示在浏览器。
具体需求：例如“导出任务的显示标题在任务列表和详情页展示时，必须作为文本而非可执行 HTML/脚本处理”。
验收：包含标签/事件属性的标题不产生可执行节点；保留合法文字与 Unicode；按 HTML/属性/URL 等真实输出上下文处理。确需富文本时，对允许的内容进行相应净化，不能直接标可信。
边界：只展示标题仍存在浏览器解释边界，但不意味着标题流入 SQL、命令或文件系统；不能用“所有输入都转义一次”替代上下文处理。来源：[XSS]。

## [P06] 服务端访问外部地址（A01）

触发：服务器依据外部 URL、回调地址或远程资源标识建立连接。
具体需求：连接目标和协议不得超出该业务获准访问的目的地；从目标解析到连接及重定向不能突破范围。
验收：对不允许的回环/元数据/内部管理目标不建立连接；域名解析和跳转后的实际目标仍受约束，或禁用非必需跳转；合法业务内部目标保留精确授权例外。
边界：校验 URL 语法不等于目标获准；客户端自己打开 URL 不自动构成服务端请求；未描述服务端出站流时不套 SSRF 需求。来源：[SSRF]。

## [P07] 上传、解析与文件边界（A02、A05、A06）

触发：服务接收并解析外部文件，或将外部名称用于存取文件。
具体需求：只允许本业务支持的文件进入对应解析器；保存位置不得由外部名称逃出指定范围，文件不能通过其存储位置获得执行能力。
验收：内容类型与业务允许格式一致，不能只相信请求 MIME；路径穿越/覆盖别人的对象失败。体积、解压后规模和解析资源上限按实际格式独立形成资源控制，不捏造固定 MB 值。
边界：只有实际归档解压才检查压缩炸弹；不为所有文件强制购买杀毒/CDR，不把沙箱建议变成运行目标或动态验证的权限。来源：[UPLOAD]。

## [P08] 敏感数据的传输保护（A04）

触发：凭证、私有数据或控制指令跨真实网络信任边界传递。
具体需求：明确该网络段的敏感数据保密与完整性保护，并验证对端身份；无法验证时不发送受保护内容。
验收：凭证不通过明文网络请求/URL传播；服务端连接不能跳过证书/对端验证；失败不降级成明文。明确 TLS 终止位置及终止后的保护责任。
边界：不为进程内参数传递强制 TLS，不凭空规定 mTLS、证书厂商或算法值；代码提供机制与生产实际 TLS 配置分别判断。来源：[TLS]、[T04]。

## [P09] 敏感副本、存储与秘密（A01、A04）

触发：私有数据复制到导出、缓存、对象存储、备份，或系统持有密码/令牌/密钥。
具体需求：副本的读取者不得因存储位置变化扩大到未授权主体；与实际威胁相关的存储保护和密钥访问单独明确。
验收：私有导出不能经公开桶或绕过下载授权的路径读取；应用秘密不随源码或面向普通用户的配置返回；密码如由本系统存储则采用专用不可逆密码存储机制，而不是明文/可逆加密。
边界：知道需要保护不等于可凭空指定 AES 型号、KMS 产品、固定轮换期；只消费 SSO 不额外要求维护本地密码；不把公开审计 JTI 当 bearer 秘密。来源：[T04]、[AUTHZ]。

## [P10] 日志中的凭证和敏感正文（A09）

触发：系统处理认证秘密/敏感内容并产生日志、异常或诊断输出，尤其日志读者比数据读者更广。
具体需求：例如“导出 API 和工作器的运行日志不得将 bearer 会话凭证或私有发票正文暴露给无相应读取权限的日志读者”。
验收：成功、拒绝、异常、调试分支都不直接写入 Authorization/会话秘密或敏感正文；必要关联使用不具认证能力的标识，清理外部日志字段以免伪造事件。
边界：发票正文与 bearer 凭证是两个检查对象，任一遗漏不算完整；不要禁止所有用户标识、所有日志或公开 JTI。业务确需记录受保护数据时，必须单独论证读者/用途/保护，不以“用于排错”直接放行。来源：[LOG]。

## [P11] 可归属审计与告警（A09）

触发：发生高价值访问、权限/安全配置变化或需调查的业务动作。
具体需求：对明确动作记录可关联的主体、对象、动作、结果和时间；防止无权限主体伪造、修改或删除记录。
验收：例如创建/下载/取消任务各有相应活动记录，委托管理员不遗漏；拒绝的重要操作有可判读结果。实际要求告警时指定可识别事件及发送责任，阈值未知则不伪造数字。
边界：性能计数指标不是安全审计替代品；日志生产、篡改保护、实际留存、告警接收为不同责任。生产实际保留要求可为 NOT_CODE_VERIFIABLE，不因此删除。来源：[LOG]、[T09]。

## [P12] 资源与业务滥用（A06、A10）

触发：不可信主体能反复触发高成本计算、文件生成、队列积压或外部调用，并影响共享服务。
具体需求：对该具体操作实施有界的准入/并发/资源分配，使单个主体不能无界占用共享资源；超限请求在占用昂贵资源前受控拒绝或延迟。
验收：用户改变对象、重复提交、批量扩大不能绕开有效预算；拒绝/取消/异常后释放受控资源；合法授权不是绕过资源约束的理由。策略数值和具体算法未定时保留配置责任，不捏造固定阈值。
边界：不写“任何合法请求必须始终成功”；不为没有高成本或共享资源前提的函数强制配额。来源：[T06]、[T10]。

## [P13] 并发、重复与状态完整性（A06、A10）

触发：设计存在至少一次交付、重试、并发取消、计费或其他不可逆动作。
具体需求：例如“完成前已生效的取消必须阻止结果发布；重复处理同一任务不得重复发布或计费”。不同安全目的分别立项。
验收：发布依据持久状态与动作顺序进行；取消先于完成生效才阻止后续发布，已完成后的取消不被错误倒推；重试/超时后的重复回调不会重复不可逆操作。
边界：可以用事务、条件更新或等效机制，不要求唯一锁产品；不把不得公开结果扩大成不得写私有临时文件；资源清理单独调查。来源：[T06]、[T10]。

## [P14] 来自外部的数据、回调和制品的可信性（A08）

触发：不可信输入影响支付/完成状态，或系统下载并加载更新、插件、序列化对象。
具体需求：在采用内容或改变状态前验证其可信来源和完整性；业务关键内容、对象与请求上下文保持绑定。
验收：伪造或被修改的回调不改变业务状态；回放是否被接受符合该动作的幂等/时效规则；更新/插件只有通过获准来源和完整性检查才能加载。
边界：不是每个私有队列都必须额外 HMAC；不把普通 JSON 解析等同可执行反序列化；未有下载/加载路径不强加升级器要求。来源：[T08]。

## [P15] 配置与攻击面（A02）

触发：管理入口、调试接口、跨域、存储公开策略或安全功能开关影响本次系统。
具体需求：例如“生产对外错误响应不暴露堆栈、数据库语句和凭证；调试入口不得在普通业务权限下暴露”。
验收：新部署默认不会给予普通调用者管理权限；配置缺失不能关闭必需控制；升级/关闭功能时保留设计明确允许的兼容/恢复路径。
边界：健康检查可以按其信息和暴露范围公开；不为所有入口禁止跨域，不把未来计划/非目标变成永久禁止；实际部署事实与代码默认值分开。来源：[T02]、[ERROR]。

## [P16] 依赖、构建与更新供应链（A03）

触发：设计确有依赖引入、构建发布、插件或自动更新，且属于本系统交付责任。
具体需求：使用可确定身份/版本的获准依赖或制品，防止未获准内容进入加载/发布路径；构建秘密与发布权限不暴露给不可信输入。
验收：依赖/制品身份可追溯；替换来源或篡改制品不能绕过本路径的验证；实际制品使用的依赖纳入维护责任。
边界：不因任何项目都依赖软件就把整个企业人事/采购/双人审批强制分配到业务代码；代码、构建配置与运营责任分别说明。来源：[T03]。

## [P17] 异常不绕过保护（A10）

触发：敏感操作依赖身份、权限、状态或外部服务判断，或失败会留下占用/部分提交。
具体需求：例如“权限服务超时或返回无法判定的结果时，不得读取、发布或取消受保护任务；只返回受控错误，不暴露秘密”。
验收：异常/空结果不回退到默认允许；失败后不留可被误用的半成品状态、不重复不可逆动作；可恢复资源释放或转入有界恢复责任。
边界：不要求捕获并忽略所有异常；安全拒绝不等于必须崩溃；不把完整业务都判失败而忽略原文允许的安全降级。来源：[T10]、[ERROR]。

## [P18] 浏览器自动携带凭证的状态变更（A01）

触发：浏览器自动附带 cookie 等凭证，且入口能创建、取消或修改受保护状态。
具体需求：状态变更不能仅因浏览器附带会话 cookie 就被跨站来源代为触发；验证该交互来自获准上下文。
验收：跨站伪造的取消/修改请求不改变状态；采用与实际交互相符的 CSRF token、来源/元数据校验等机制，合法客户端保持可用。
边界：不将 SameSite 一项视作所有场景的唯一保护；仅使用客户端主动添加 Authorization 且没有自动携带凭证的接口，不凭空要求 cookie CSRF 方案。来源：[CSRF]。

## 六个角色如何使用

- 设计分析：寻找模式所需的真实前提，尤其敏感字段、读者、取消入口、外部依赖和浏览器输出；未描述机制不妨碍记录已知暴露。
- 需求生成：按适用前提实例化具体需求。每条 rationale 简述“设计前提 → 风险路径 → 控制目的”，可标本地 P 编号；origin=INFERRED_SECURITY，引用实际设计段落，而非把本手册当项目来源。
- 需求复核：先构造一个违反控制的具体例子，再检查原文前提、保护是否足够和合法例外。授权检查不可缺，不代表原文已实现授权。保留更新标签这一合法恢复路径，不等于禁止 TokenRequest 等其他路径；不要把未提另一可选路径解读为明确禁止它。
- 标准匹配：模式只帮助形成查询与语义判断，正式匹配仍只选择已保存固定控制；不要现场生成 OWASP/PCI 条款或将方法编号当合规 ID。
- 实现检查：按具体操作、字段和副作用追踪支持/反证，不能以函数名字或框架存在证明满足；部署事实照常标记无法通过代码验证。
- 历史规范兼容生成：忠实转换目标规范原义，不因本手册有更多建议就为规范扩张义务。
